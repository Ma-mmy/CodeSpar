# CodeSpar 产品需求文档（PRD v0.1）

## 1. Context：为什么做这个

你是 Agent 方向的工程师，需要持续为面试做准备。现有的刷题产品（LeetCode / 牛客 / 八股文合集）存在两个硬伤：

1. **题库跟不上**：Agent / LLM 应用工程这个方向变化极快（RAG、Function Calling、Multi-Agent、Context Engineering、Eval），公开题库要么没有，要么陈旧。
2. **无法定向**：你想针对「上周面试被问倒的那个点」出 20 道题猛攻，现成题库做不到。

**核心思路**：不维护静态题库，而是**把出题这件事本身交给大模型**——你写一段提示词描述想考什么，加上结构化参数（题型、数量、难度、知识点），由你指定的模型现场生成一整套试卷；答完后由模型对照出题时同步产出的评分要点阅卷、打分、点评。所有题目与阅卷结果沉淀下来，形成**你个人的、按知识点标记的能力画像**，从而知道下一轮该攻哪里。

**产品定位一句话**：一个由 LLM 驱动的、面向 Agent 工程师的个人模考与复盘系统。

**预期产出**：本地运行的 Web 应用，单人使用，数据存本地。

## 2. 已确认的产品决策

以下 7 项已与你确认，是本 PRD 的前提约束：

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 部署形态 | 本地单人使用，无账号体系，数据落本地。可选本机访问口令；公网远程须经 HTTPS 反代 |
| 2 | 支持题型 | 概念问答题、系统/架构设计题、选择/判断题、填空题（**不含**代码实现题与沙箱执行） |
| 3 | 阅卷模式 | 出题时同步生成参考答案 + 评分要点，交卷后由指定模型对照要点打分 |
| 4 | 模型接入 | 统一走 OpenAI 兼容协议（baseURL + apiKey + model），一套代码通吃 |
| 5 | 答题节奏 | **仅整卷模考**：一次生成 N 道题成卷 → 全部答完 → 一次性交卷阅卷 → 出总分报告 |
| 6 | 题库 | 所有生成的题入库沉淀，出新题时自动去重，避免反复出同一道 |
| 7 | 弱项追踪 | 核心能力：知识点标签 → 薄弱项统计 → 错题本 → 一键针对性重刷 |

## 3. 核心概念（术语表）

统一术语，避免后续讨论时鸡同鸭讲：

- **模型配置（Model Profile）**：一条 OpenAI 兼容的模型接入配置。含名称、baseURL、apiKey、model 名、用途角色（可出题 / 可阅卷）。
- **出题任务（Generation Job）**：一次「按提示词+参数生成试卷」的执行记录。是**出题历史**的载体。
- **题目（Question）**：一道题的实体，含题干、题型、难度、知识点标签、参考答案、评分要点、来源出题任务。入题库、可复用。
- **试卷（Exam）**：一次模考的载体。由 N 道题目组成，有状态（未开始 / 作答中 / 已交卷 / 已阅卷）。
- **作答（Answer）**：你对某道题在某张试卷中的回答。
- **阅卷结果（Grading）**：某张试卷的批改产物，含每题得分、点评、命中/遗漏要点，以及总分与标签维度分。是**阅卷历史**的载体。
- **知识点标签（Tag）**：如 `RAG`、`Function Calling`、`Multi-Agent`、`Prompt Engineering`、`Eval`、`Context Engineering`。标签是弱项统计的聚合维度。
- **提示词预设（Prompt Preset）**：可保存复用的出题提示词 + 参数组合。

## 4. 功能需求

### 4.1 模块一：模型管理（P0）

**目的**：让你自由决定"让哪些大模型出题、让哪个模型阅卷"。

**功能点**：

- **F1.1 添加模型配置**。表单字段：
  - 显示名称（如 `DeepSeek-V3`、`Kimi-K2`、`GPT-5-via-OpenRouter`）
  - baseURL（如 `https://api.deepseek.com/v1`）
  - apiKey
  - model 名（如 `deepseek-chat`）
  - 角色开关：`可用于出题` / `可用于阅卷`（可同时勾选）
  - 可选高级参数：temperature、max_tokens、是否支持 JSON 模式
- **F1.2 连通性测试**。保存前有「测试连接」按钮，发一条极短请求验证 key 与 model 名正确，返回延迟与响应片段。**这一步很关键**——避免出题跑到一半才发现配置错了。
- **F1.3 列表管理**：增删改查、启用/禁用、设置默认出题模型与默认阅卷模型。
- **F1.4 密钥安全**：apiKey 在 UI 上默认掩码显示；日志与历史记录中**绝不落库明文 key**。

**验收**：能同时配置 ≥3 家不同厂商的模型，任选其一出题成功。

---

### 4.2 模块二：出题（P0，核心）

**目的**：这是产品的心脏——你写提示词，AI 给你出一整套可考的题。

#### F2.1 出题表单

| 字段 | 说明 | 必填 |
|------|------|------|
| **出题提示词** | 大文本框。自由描述想考什么。例：「围绕生产级 RAG 系统的检索质量优化出题，重点考察召回率与精确率的取舍、rerank 策略、chunk 策略的实际权衡，题目要贴近真实故障排查场景，不要考背诵定义」 | 是 |
| **题型与数量** | 每种题型独立设置数量（如：选择 5、填空 3、概念问答 4、系统设计 1）。每种题型上限 20，可保存为出题页「使用预设」的默认数量 | 是 |
| **难度** | 初级 / 中级 / 高级 / 专家。也可按题型分别设难度 | 是 |
| **知识点标签** | 可从已有标签库多选，也可自由输入新标签。用于后续弱项聚合。留空则由模型自动为每题打标 | 否 |
| **出题模型** | 从「可出题」的模型配置中选择 | 是 |
| **语言** | 中文 / 英文（面试可能是英文的） | 否，默认中文 |
| **去重强度** | 关闭 / 标准 / 严格。见 4.3 | 否，默认标准 |

#### F2.2 提示词预设（Prompt Preset）

- 出题表单可整体「另存为预设」，含提示词与所有参数。
- 预设列表可一键载入，减少重复输入。
- **内置若干起步预设**（降低冷启动成本），例如：
  - 「Agent 架构设计专项」
  - 「RAG 工程实战专项」
  - 「LLM 基础八股速刷」（纯客观题，快、省 token）
  - 「Multi-Agent 协作与通信」
  - 「模拟真实面试轮」（混合题型，模拟一轮 60 分钟技术面）

#### F2.3 生成过程

- 点击「生成试卷」后展示**实时进度**：正在生成第几题 / 已生成 N 题、耗时、累计 token 消耗。
- 支持**中途取消**。已生成的部分可选择保留或丢弃。
- **结构化输出**：要求模型返回严格 JSON。解析失败时自动重试（最多 2 次），仍失败则展示原始输出并允许手动修正/丢弃该题。
- 生成结果**进入预览页**而非直接开考：你可以逐题查看题干与参考答案，**删除不满意的题**、**要求重新生成某一题**（可附加修改意见，如"这题太简单了，加大难度"），确认后才生成试卷。

#### F2.4 每道题模型需产出的字段

这是阅卷能力的基础，出题时就必须一并产出：

- `题干`
- `题型`
- `难度`
- `知识点标签`（1-3 个）
- `参考答案`（详尽版，也是你复盘时的学习材料）
- `评分要点 rubric`：得分点列表，每点带分值权重。例如系统设计题："提出了分层检索方案 (3分)"、"讨论了延迟与召回的取舍 (3分)"、"给出了可观测性方案 (2分)"、"考虑了失败降级 (2分)"
- `满分`
- 客观题额外：`选项列表`、`正确选项`、`答案解析`
- 填空题额外：`标准答案`、`可接受的同义表述列表`

**验收**：给定一段提示词，能稳定生成含以上完整字段的 N 道题，JSON 解析成功率 > 95%。

### 4.3 模块三：题库与去重（P0）

**目的**：避免"刷了三轮，每轮都是同一道题"。

- **F3.1 题目入库**：所有确认生成的题目永久入库，可按标签、题型、难度、来源模型、时间检索。
- **F3.2 出题去重**（两道防线）：
  1. **事前防线（Prompt 注入）**：生成前，从题库中检索与本次「知识点标签 + 提示词」相关的历史题干（取最近 N 条，N 随去重强度调整），**摘要后拼进出题提示词**，明确要求模型"避开以下已出过的题，从新角度切入"。
  2. **事后防线（相似度过滤）**：生成后，对新题题干与库中同标签题目做文本相似度比对，超过阈值的标记为「疑似重复」并在预览页高亮提示，由你决定保留或替换。
     - 去重强度：`标准` = 只标记提示；`严格` = 自动剔除并触发补生成。
- **F3.3 题目复用**：可从题库手动挑题**组卷**（不调用模型，零成本），用于「错题重刷」和「考前突击」。
- **F3.4 题目编辑**：题库中的题可手动编辑题干/参考答案/评分要点/标签——模型偶尔会出错题，你要能修。

---

### 4.4 模块四：模考答题（P0）

**目的**：模拟真实面试环境，一次性作答完整试卷。

- **F4.1 试卷视图**：
  - 左侧：题号导航栏，标记每题状态（未答 / 已答 / 标记待定）。
  - 主区：当前题目题干 + 作答区。
    - 客观题：单选/多选/判断的选项控件
    - 填空题：短输入框（支持多空）
    - 概念问答 / 系统设计：Markdown 大文本框，支持实时预览
  - 顶部：计时器。支持**可选限时**（如 60 分钟），到时提醒但不强制交卷。
- **F4.2 草稿自动保存**：作答内容持续本地保存，刷新/关闭浏览器不丢失，可随时中断后继续。
- **F4.3 答题时不可见答案**：参考答案与评分要点在交卷前一律不展示。
- **F4.4 交卷**：二次确认（提示未答题数），交卷后进入阅卷流程。

---

### 4.5 模块五：阅卷（P0，核心）

**目的**：给出可信、可学习的评分与点评。

- **F5.1 分层判分**：
  - **客观题（选择/判断）**：本地直接判分，**不调用模型、不消耗 token**。
  - **填空题**：先与标准答案及同义表述列表做规范化匹配；命中则本地判分；未命中则交由模型判定是否语义等价（避免"表述不同但正确"被误判）。
  - **主观题（概念问答 / 系统设计）**：调用阅卷模型，输入 = 题干 + 参考答案 + 评分要点 rubric + 你的作答，输出结构化评分。
- **F5.2 阅卷模型选择**：交卷时可指定本次用哪个模型阅卷（默认用设置里的默认阅卷模型）。**允许与出题模型不同**——即使 MVP 不强制交叉阅卷，也把选择权留给你。
- **F5.3 阅卷输出（每道主观题）**：
  - 得分 / 满分
  - **逐个评分要点的命中情况**（命中 / 部分命中 / 遗漏），这是最有价值的部分——精确告诉你漏了什么
  - 文字点评：答得好的地方、不足、改进建议
  - 参考答案对照展示
- **F5.4 阅卷进度**：主观题并发调用（限制并发数），展示进度条。单题失败可单独重试，不影响整卷。
- **F5.5 人工复核**：你可以**手动覆盖 AI 给的分数**并记录理由——AI 判分偶有偏差，你的判断是最终裁决，且覆盖数据能反映 AI 阅卷的可靠度。
- **F5.6 成绩报告页**：
  - 总分、得分率、各题型得分分布、用时
  - **按知识点标签的得分率**（本次考试的雷达/条形图）
  - 逐题展开：你的作答 / 参考答案 / 要点命中 / 点评
  - 一键操作：「把低分题加入错题本」、「针对本次弱项标签再出一套题」

---

### 4.6 模块六：历史记录（P0）

两类历史，分开呈现：

- **F6.1 出题历史**：每次出题任务一条记录。
  - 展示：时间、提示词（可展开全文）、参数、出题模型、生成题数、token 消耗、耗时、成功/失败
  - 操作：**「用相同参数再来一次」**（自动带去重）、查看生成的题、把参数存为预设
- **F6.2 阅卷/考试历史**：每张已阅卷试卷一条记录。
  - 展示：时间、试卷名、题数、总分与得分率、用时、出题模型、阅卷模型
  - 操作：查看完整报告、**重刷此卷**（同题重做，对比两次得分，看是否真的掌握了）
- **F6.3 筛选与检索**：按时间范围、标签、模型、得分区间筛选。

---

### 4.7 模块七：弱项分析与错题本（P0）

**目的**：让刷题变成有方向的训练，而不是盲目做题。

- **F7.1 能力仪表盘**：
  - **知识点得分率排行**：按标签聚合所有历史阅卷数据，从低到高排序，一眼看到最弱的 5 个标签（含每个标签的题量，题量太少时标注"样本不足"）
  - **趋势曲线**：整体得分率随时间变化；单个标签的得分率变化（验证"我最近攻的 RAG 是不是真有进步"）
  - **题型维度得分率**：判断是"知识不牢"还是"设计题表达能力弱"
  - **累计统计**：总做题数、总考试场次、总 token 消耗（顺带控成本）
- **F7.2 错题本**：
  - 自动入库规则：得分率 < 阈值（默认 60%，可配置）的题自动进错题本
  - 手动增删
  - 展示：题干、你当时的作答、参考答案、点评、错误次数、最近一次时间
  - **重刷**：从错题本一键组卷（可按标签筛选、限定数量），重做后若达标可自动移出（可配置为"连续 2 次达标才移出"）
- **F7.3 定向出题入口**：仪表盘的每个弱项标签旁有「针对此项出题」按钮，点击后直接跳到出题页并预填该标签与建议提示词。

## 5. 关键用户流程

### 流程 A：日常刷题（主流程）

```
打开仪表盘 → 看到「Multi-Agent 得分率 45%，最弱」
  → 点「针对此项出题」
  → 出题页已预填标签，补写提示词：「重点考察多 Agent 的任务分解与冲突消解」
  → 设置：选择 4 题 + 概念问答 3 题 + 系统设计 1 题，难度=高级，模型=DeepSeek
  → 生成（30s，实时进度）
  → 预览：删掉 1 道太浅的题，让模型重出一道
  → 开考（限时 45 分钟）
  → 逐题作答，中途去吃饭，回来继续（草稿已存）
  → 交卷 → 选择 Kimi 阅卷 → 进度条 → 成绩报告
  → 得分 68%。展开系统设计题，发现漏了「冲突消解的仲裁机制」这个要点
  → 低分题自动进错题本
  → 三天后从错题本重刷，对比得分
```

### 流程 B：模拟真实面试轮

```
出题页 → 载入预设「模拟真实面试轮」
  → 混合题型 8 题，难度=高级，限时 60 分钟
  → 全程作答不中断 → 交卷 → 报告 → 复盘参考答案
```

### 流程 C：考前速刷八股

```
出题页 → 载入预设「LLM 基础八股速刷」
  → 20 道纯客观题 → 作答 → 交卷
  → 客观题本地判分，秒出结果，零阅卷 token 消耗
```

## 6. 数据模型概要

不涉及具体技术选型，仅描述实体关系（供后续技术方案细化）：

```
ModelProfile   模型配置（名称、baseURL、key、model、角色、默认标记）
Tag            知识点标签（名称、题目数、累计得分率——可实时算亦可缓存）
PromptPreset   提示词预设（名称、提示词、参数快照）

GenerationJob  出题任务（提示词、参数、模型、状态、token、耗时、时间）
  └─ 1:N ─> Question  题目（题干、题型、难度、参考答案、rubric、满分、选项、
                             标签[N:N]、来源 job、是否手动编辑过）

Exam           试卷（名称、状态、限时、开始/交卷时间、阅卷模型、总分、得分率）
  └─ N:N ─> Question（通过 ExamQuestion 关联，记录题序）
  └─ 1:N ─> Answer    作答（题目、作答内容、是否标记待定）
  └─ 1:1 ─> Grading   阅卷结果（总分、报告摘要、阅卷模型、时间）
       └─ 1:N ─> QuestionGrading  单题评分（得分、要点命中详情、点评、
                                    是否被人工覆盖、覆盖理由）

WrongQuestion  错题本条目（题目、错误次数、最近错误时间、状态、是否手动加入）
```

**要点**：`Question` 独立于 `Exam` 存在，这是题库沉淀与错题重刷的基础；`Tag` 与 `QuestionGrading` 的关联是弱项统计的数据来源。

## 7. 非功能需求

- **NFR1 本地优先**：所有数据存本地，除调用 LLM API 外不与任何外部服务通信。
- **NFR2 密钥安全**：apiKey 不出现在日志、历史记录、导出文件中；UI 默认掩码。
- **NFR3 成本可见**：每次出题/阅卷记录 token 消耗；仪表盘展示累计消耗。避免刷题刷出账单惊喜。
- **NFR4 韧性**：LLM 调用失败/超时/JSON 格式错误必须有明确报错与重试，**不能静默丢题**；长任务可中断，中断后已产出的内容不丢。
- **NFR5 响应性**：生成/阅卷这类长任务全程有进度反馈，不出现"点了按钮无反应"。
- **NFR6 数据可导出**：题库与历史支持导出（JSON / Markdown），便于备份，也便于把参考答案导出成复习资料。

## 8. 迭代范围建议

MVP（P0）已经不小，建议分两步走：

**Step 1 — 打通闭环（先能用起来）**
模型管理（含连通测试）→ 出题（表单 + 生成 + 预览）→ 组卷答题 → 阅卷 → 成绩报告 → 出题历史 + 阅卷历史

**Step 2 — 形成飞轮（让刷题有方向）**
题库检索与去重 → 知识点标签体系 → 能力仪表盘 → 错题本与重刷 → 提示词预设

**P1（后续增强）**
- 交叉阅卷 / 多模型陪审团评分（数据模型上 `Grading` 已预留了阅卷模型字段，扩展成本低）
- 同一提示词让多个模型分别出题，横向对比出题质量
- 间隔重复（SRS）调度错题复习节奏
- 代码实现题 + 沙箱执行

**P2（远期）**
- 语音模拟面试（口述作答）
- 多用户 / 云端同步 / 题库分享

## 9. 待确认问题（下一轮讨论）

1. **成绩报告与仪表盘的图表形态**：雷达图 vs 条形图？我倾向条形图（标签数量可能超过 8 个，雷达图会糊）。
2. **限时模式是否强制交卷**：目前定为"提醒但不强制"，是否需要严格模式？
3. **系统设计题的作答形式**：纯 Markdown 文本够不够？是否需要画图能力（如 Mermaid 编辑器）？
4. **默认难度与题量**：是否需要一个"每日一练"的固定配置，一键开考？
5. **token 预算保护**：是否需要设置单次出题/阅卷的 token 上限，超限自动中止？

## 10. 验收标准（MVP）

- [ ] 能配置 ≥3 家 OpenAI 兼容模型并测试连通
- [ ] 一段提示词 + 参数能稳定生成含完整字段（题干/答案/rubric/标签）的试卷，JSON 解析成功率 > 95%
- [ ] 预览页可删题、重生成单题
- [ ] 四种题型均可正常作答，草稿刷新不丢
- [ ] 客观题本地判分零 token；主观题按 rubric 逐要点评分并给出点评
- [ ] 成绩报告展示总分 + 标签维度得分 + 逐题详情
- [ ] 出题历史可「相同参数再来一次」且不出重复题
- [ ] 阅卷历史可回看完整报告并「重刷此卷」
- [ ] 仪表盘正确聚合出弱项标签排行
- [ ] 低分题自动进错题本，可从错题本组卷重刷
